# 国王大道交互 HTML · 功能版 v1

## 打开作品

下载仓库根目录的 [overwatch-diorama.html](../overwatch-diorama.html)，在支持 WebGL2 的浏览器中双击打开。用户运行作品不需要安装 npm、启动服务器、连接互联网或另行下载模型。

## 已实现

- 同一个三维场景中的国王大道建筑、街道、电话亭、护送车、三位风格化英雄、护盾和闪现轨迹。
- 五个相机预设：展示、正面、顶面、右侧、背面；旋转、缩放、平移和复位。
- 七个独立灯光分区：主路灯、巷内壁灯、电话亭、四个房间。
- 点击物件开关灯光；对象列表与选中面板提供自动 / 常亮 / 关闭和亮度控制。
- 同一房间的正面、侧面与背面窗户共用房间状态。实墙遮挡点击，透明特效不阻挡点选。
- 时间滑块、四个时段快捷按钮、播放 / 暂停、0.5× / 1× / 2×速度。
- 自动灯光跟随昼夜；手动灯光保持设置；拖时间会暂停播放；切后台暂停时间累积。
- 鼠标、键盘与触屏操作；双指操作与相机拖拽不会误切灯光。
- 中文界面、操作帮助、键盘焦点、低性能软件渲染降档和 WebGL 不可用时的明确提示。

默认 18:30、时间暂停、所有灯光自动。点“重置场景”恢复默认；复位镜头只改视角，不改灯光或时间。

## 模型来源与视觉范围

最终 HTML 的建筑、道具、三位角色和材质全部由原创程序化几何构建，没有嵌入提取的游戏模型，也没有使用参考图片作为三维场景的替代。整体遵循固定空间与卡通方向，角色和细节的精细度与概念图存在差距。

原始资产转换也做了实际验证：当前 SourceIO 版本依赖云环境未提供的 GLIBC 2.43；改用较早官方版本并处理路径兼容后，国王大道护送车成功导入 Blender，得到 12 个网格、50,259 个顶点、12 个材质。路灯仍受旧材质绝对路径问题影响，未声称导入成功。详情见 [source-import-report.json](validation/source-import-report.json)。这些验证结果不代表该模型已经用于 HTML。

## 测试证据

- [浏览器验收报告](validation/browser-report.json)：文件大小、SHA256、离线运行、交互用例和连续运行记录。

- [Firefox 独立验证](validation/firefox-report.json)：使用 Xvfb 虚拟显示和 Mesa 软件图形驱动。无显示模式缺少 WebGL 驱动的问题已单独诊断。

- [正面](validation/front.png)、[顶面](validation/top.png)、[右侧](validation/right.png)、[背面](validation/back.png)。

状态逻辑测试通过 `npm test` 运行，共 9 项，覆盖手动优先级、分区独立、亮度记忆、时间暂停、午夜循环、低帧率时间推进和太阳轨迹连续性。

测试过程中发现并修复了：内联脚本封装中的特殊字符替换、动态物件绘制次数过高、低性能设备阴影负担、界面遮挡底座、手机触控区域偏小，以及低帧率下场景时间流逝变慢。

## 验收边界

核心交互和离线运行有自动化与截图证据。物理手机、真实集成显卡 / 独立显卡设备的帧率、Safari、所有辅助技术组合仍需单独实测；桌面缩小窗口不等于移动实机性能验收。

云端 Chromium 使用 SwiftShader、Firefox 使用 Mesa 软件渲染，报告中的 FPS 如实记录。它们不能作为规范中主流显卡 45–60 FPS 目标已经达成的证据。本版不作“所有性能目标和所有平台均已验收”的声明。

## 源码位置

| 文件 | 用途 |
| --- | --- |
| `web/scene.js` | 原创场景与角色几何、房间窗面、灯具、静态与交互模型合批 |
| `web/state.mjs` | 灯光模式、亮度、时间和优先级规则 |
| `web/main.js` | 渲染、相机、拾取、时间更新和界面联动 |
| `web/template.html` / `web/style.css` | 中文界面与响应式样式 |
| `web/build.mjs` | 打包为无运行时外部依赖的一个 HTML |
| `tools/test_html.py` | 浏览器功能、截图和连续运行验收 |
| `tools/test_touch.py` | 触屏输入与多指操作验证 |

构建命令见 [README](../README.md)。后续精细化模型时，应保留物件 ID、七个灯光分区和状态规则，替换外观无需推倒重写交互系统。
