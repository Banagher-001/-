# 守望先锋微缩场景 HTML 制作执行标准 v1.0

制定日期：2026-10-30。本文是后续制作与验收基线，不代表 HTML 或交互功能已经完成。

## 1. 最终交付

交付一个 `overwatch-diorama.html`，将国王大道卡通微缩场景作为可旋转、缩放、点选的实时三维作品展示。用户可以点击灯具和房间切换灯光，调整一天中的时间，并观察昼夜光照变化。

强制交付条件：

1. HTML 自包含：脚本、样式、模型、贴图、图标和必要解码代码全部内嵌。
2. 在支持 WebGL2 的桌面浏览器中，直接双击 HTML，即 `file://` 打开即可运行；不要求安装软件、启动服务器、登录或联网。
3. 使用 HTTP 打开同一文件也正常；断开互联网后，仍能加载和操作全部核心功能。
4. 运行时不依赖 CDN、远程模型、远程字体、远程贴图和额外同级文件。浏览器内部的 `blob:` / `data:` 资源允许使用。
5. 同一个三维场景提供四方向观察。灯光、时间和相机交互都作用于此场景。
6. 配套源码、制作记录和测试证据可保存在仓库；用户运行最终作品只需这一个 HTML。

## 2. 制作依据与优先级

当依据之间存在差异时，按以下顺序处理：

1. 本文确定的功能与交付要求。
2. [固定布局 JSON](../design/layout-v1.json)：物件位置、占地、朝向和相对尺度。
3. [同坐标四向正投影占位图](../design/layout-v1.png)：空间与遮挡核对。
4. [四方向参考图](../design/README.md)：造型、材质、色彩、灯光和叙事。
5. 获取到的原始模型：作为素材进行调整，不能反过来改变已经固定的核心构图。

现有生成图片存在视角和细节漂移。最终 HTML 的四视图必须从同一三维场景获得；背面、侧面不得为露出角色而重新摆放模型。最终成品需在固定相机下与空间占位图核对，而不能只截取一个漂亮角度交付。

## 3. 场景范围与空间标准

### 3.1 必须出现的内容

| 类别 | 必须内容 | 完成判断 |
| --- | --- | --- |
| 展示底座 | 深色倒角底座、石板道路、人行道、路缘 | 四边完整，无悬空或穿出底座的主体 |
| 建筑 | 后方红砖双层建筑、浅色石材窗套、封闭屋顶与背墙 | 正、侧、背面都有完整造型 |
| 小巷 | 右侧剖面砖墙、壁灯、排水管、垃圾箱 | 从正面能辨识巷口，侧背面遮挡合理 |
| 城市道具 | 左后电话亭、主路灯、围栏、路桩、窗台花箱 | 与建筑保持统一卡通比例 |
| 中心物件 | 一辆风格化护送车、橙色核心、悬浮部件 | 正面焦点清晰，不压住人物主体 |
| 角色 | 左前猎空、右前莱因哈特、右后死神 | 有角色辨识度、明确动作和完整轮廓 |
| 特效 | 青蓝色护盾、猎空闪现轨迹 | 半透明、轻发光，不大面积遮挡场景 |
| 可交互房间 | 两层各两个房间，共四个独立灯光分区 | 同一房间不同方向的窗户保持同一状态 |

### 3.2 坐标与比例

- 设计单位为厘米：底座 40×34×3，地面 Z=0，底座向下至 Z=-3；这不是官方游戏尺寸或已经核定的打印尺寸。
- X 向正面观察者右侧，Y 从前沿 0 指向后沿 34，Z 向上。
- 主建筑 X=-4…12、Y=24…33，高 26；小巷右墙 X=17.5…18.5、Y=22…33，高 16。
- 电话亭中心 (-14,25)，主路灯 (-15,17)，护送车 (0,16)。
- 猎空中心 (-10,6)，莱因哈特 (10,10)，死神 (15,27)。
- 具体占地与高度读取布局 JSON。角色动作、武器和特效的轮廓可延伸，但不能侵入其他主体的主要视觉区域；需要明显改变占地时，先同步修订布局版本和四方向占位图。
- 如果引擎采用 Three.js 的 Y 向上坐标，统一转换为 `world=(X,Z,-Y)`。转换只做一次，保留逻辑坐标，避免各资产自行旋转导致朝向混乱。

### 3.3 房间分区

| 稳定 ID | 中文名称 | 正面观察的位置 | 对应窗户 |
| --- | --- | --- | --- |
| ROOM_GF_L | 一层左房间 | 下层左 | 正面下左及该房间的其他外窗 |
| ROOM_GF_R | 一层右房间 | 下层右 | 正面下右及该房间的其他外窗 |
| ROOM_F1_L | 二层左房间 | 上层左 | 正面上左、后侧相应外窗 |
| ROOM_F1_R | 二层右房间 | 上层右 | 正面上右、后侧及右侧相应外窗 |

每层以建筑 X=4 为左右分区线。房间具有简单内壁、窗后纵深和遮光分隔，避免所有窗户像贴在墙上的同一张黄色图片。外部观察是核心流程；完整室内装修、进屋漫游和屋顶拆装属于后续扩展。

## 4. 美术质量标准

### 4.1 整体风格

- 卡通收藏级树脂模型感：饱满轮廓、适量倒角、干净块面、半哑光材质。
- 红砖与暖石材为环境主色，橙色护送车核心与青蓝色特效形成焦点。
- 角色需统一比例和材质；不能保留一个写实高模、一个打印白模、一个卡通低模的混合状态。
- 保留猎空的护目镜、胸口装置与双枪；莱因哈特的厚重装甲、大锤与护盾；死神的兜帽、面具和双枪。
- 日间能读清材质和轮廓；夜间突出暖窗、街灯和能量效果，同时保留建筑与角色暗部细节。

### 4.2 材质与细节

- 护送车及英雄装甲保留适量金属反光，砖墙和地面不过度镜面化。
- 砖缝、石板拼接、花箱和窗框在正常观察距离可辨，近看不依赖极端高面数。
- 透明护盾须检查排序、重叠和背面表现；不允许明显黑块、闪面或角色突然消失。
- 窗户关灯后仍有玻璃和自然受光；开灯后出现暖色窗内发光及合理的附近照明。
- 发光强度受控，护盾和核心不能过曝成没有结构的色块。
- 背面至少有砖墙、窗户、石材分层和排水管，不能以空洞、透明外壳或缺失贴图交付。

## 5. 交互对象与操作标准

### 5.1 必做交互对象

| 对象 ID | 名称 | 场景点击区域 | 控制内容 |
| --- | --- | --- | --- |
| L01 | 主路灯 | 灯头、灯柱 | 灯罩发光、地面暖光与光晕同步 |
| L02 | 小巷壁灯 | 灯具本体 | 巷内局部光与灯罩发光同步 |
| P01_LIGHT | 电话亭灯 | 亭身、亭顶 | 电话亭内部照明 |
| 四个 ROOM ID | 四个房间 | 对应窗玻璃、窗框 | 该房间全部窗户及内部照明 |

以上共七个独立灯光分区。所有可见窗户均须关联到房间 ID，包括背面和侧面的窗户；同一房间的窗户不是彼此独立的随机灯。

### 5.2 点击行为

1. 鼠标悬停可交互物件时，出现轻微轮廓或高亮，光标变化，并显示简短中文名称。
2. 单击直接切换开/关，同时选中对象，在侧边小面板显示名称、状态和控制项。
3. 触屏轻触同样生效；不依赖悬停才能发现操作，提供“显示可交互物件”辅助开关。
4. 每次切换在 300 ms 内完成平滑过渡；发光材质、局部光、光晕必须一致，关灯后不能残留固定黄色窗面或光晕。
5. 不用强制弹窗或二次确认。对象名称和状态有文字显示，不能只靠颜色区分。
6. 对于被建筑实墙遮挡的窗户，不允许隔墙点击；用户可旋转相机或从对象列表选择。透明特效不得吞掉后方物件的点击。

### 5.3 手动灯光与时间的优先级

每个灯光分区均有三种模式：**自动、常亮、关闭**。

| 当前状态 / 操作 | 结果 |
| --- | --- |
| 自动模式下点击物件 | 根据当前目标亮度，切换为手动关闭或手动常亮 |
| 手动常亮时点击 | 手动关闭 |
| 手动关闭时点击 | 手动常亮 |
| 点击对象面板“自动” | 恢复跟随场景时间 |
| 调整时间或播放昼夜 | 自动对象随时间变化；手动对象保持用户选择 |
| 点击“全部恢复自动” | 七个分区统一回到自动，不重置相机和场景时间 |

自动模式点击判断使用当前**目标亮度**而非过渡中的瞬时亮度，目标达到最大亮度一半视为已亮，避免快速点击时逻辑反复。

选中对象另提供 0–100% 亮度滑块。用户主动调节即进入手动模式；调到 0 进入关闭，调到非零进入常亮。再次点击开灯恢复该对象上一次非零亮度，初始值 80%。UI 显示的亮度百分比与实际目标亮度一致。

### 5.4 相机与手势

- 桌面：左键拖拽旋转，滚轮缩放，右键拖拽平移；按钮提供复位。
- 触屏：单指旋转，双指缩放和平移；控件滑动不同时驱动相机。
- 指针移动超过约 6 CSS px 或发生多指操作，判定为相机手势，不触发灯光切换；需要对触屏抖动进行容错。
- 拖动时间/亮度滑块、点击按钮时，场景不跟着旋转。
- 限制缩放和相机位置，不能穿入建筑、钻到底座下方或把场景平移丢失。
- 点击空白区域取消选中，不改变灯光；复位相机不改变时间或灯光。

### 5.5 附加交互的优先级

完成上述核心功能后，再考虑护送车核心开关、护盾显隐、闪现轨迹流动、轻微悬浮动画。附加功能不能替代路灯、房间和时间系统的验收；角色完整战斗动画、物理碰撞和游戏玩法不属于本版必做范围。

## 6. 时间与昼夜系统

### 6.1 用户操作

- 底部提供 00:00–23:59 时间滑块，精度一分钟，显示明确的 `HH:MM`。
- 提供“黎明 06:00 / 白天 12:00 / 黄昏 18:00 / 深夜 23:00”四个快捷按钮。
- 初始时间为 18:30，默认暂停自动流逝，便于用户先观察黄昏和灯光。
- 播放后默认 120 秒完成一天；提供 0.5×、1×、2×速度及暂停。
- 手动拖动时间会暂停自动播放；用户再次点播放才恢复。切换快捷时间同样暂停。
- 一天结束平滑循环到次日；23:59 与 00:00 的环境表现连续。
- 页面切到后台或不可见时暂停累积模拟时间，返回后不追赶隐藏期间的时长。

### 6.2 时间必须改变的内容

1. 主光的方向、颜色、强度，以及对应的投影方向。
2. 环境光、背景色和天空氛围。
3. 场景整体亮度与冷暖关系。
4. 自动模式灯具、房间和电话亭的开灯程度。
5. 能量核心和蓝色特效在昼夜环境中的相对观感。

时间切换不能只给背景换颜色。阴影不能始终停留在中午方向；夜间关闭白昼强阴影，用受控的月光/环境补光保持可读性。

### 6.3 光照计算与过渡

- 使用固定的艺术化 24 小时周期，约 06:00 日出、18:00 日落，不依赖真实日期、地理位置或天气 API。
- 太阳高度与方向随时间连续变化；室外自动灯光在日出/日落前后平滑变亮或变暗，而不是整点突跳。
- 推荐以太阳高度定义夜间系数：高度低于 -6° 时为 1，高于 +6° 时为 0，中间用平滑插值。
- 自动灯的目标亮度由夜间系数计算；手动常亮/关闭优先于时间系统。
- 夜间窗光以暖色为主，环境偏冷；白天开灯依然能观察到窗面与灯罩的变化，但不产生刺眼的过曝。
- 灯光过渡按真实帧间隔计算。时间拖动时及时更新，不累计延迟动画队列。

## 7. 相机预设与四方向验收

使用正交相机作为默认展示相机，初始角度为前方约 45° 的俯视展示角。允许用户旋转，但同时提供“展示、正面、顶面、右侧、背面”五个预设。

下表坐标均使用布局的 X/Y/Z；相机指向同一个固定场景，不移动模型：

| 预设 | 相机参考位置 | 观察目标 | 方向要求 |
| --- | --- | --- | --- |
| 正面 | (0,-100,13) | (0,17,13) | 水平看向后方，X 正方向在画面右侧 |
| 顶面 | (0,17,120) | (0,17,0) | 垂直向下，Y 正方向在画面上方 |
| 右侧 | (120,17,13) | (0,17,13) | 水平向左看，场景前沿在画面左侧 |
| 背面 | (0,134,13) | (0,17,13) | 水平看向前方，X 正方向在画面左侧 |

预设正交范围自适应窗口，留出约 8% 的边距；整座底座和屋顶应可见。顶面使用与视线不共线的相机 up 向量，转换为 Three.js 坐标后可取 `(0,0,-1)`。正面/侧面/背面保持竖直向上。

普通展示视角允许短暂平滑切换；严格四视图预设停止在准确方向。点击预设不重置用户灯光、时间、亮度或播放速度。

## 8. 界面、可用性与反馈

- 全部主要界面使用中文：场景标题、时间、播放/暂停、灯光模式、亮度、视角、恢复自动和帮助。
- 画面主体是场景；桌面控制栏不大面积盖住角色，移动端选中面板可折叠。
- 对象面板展示：对象名称、自动/常亮/关闭、实际目标亮度、三个模式按钮、亮度滑块。
- 提供可折叠的灯光对象列表，能操作被遮挡的房间，也为键盘操作提供等价入口。
- 按钮和滑块可通过 Tab、回车、空格与方向键操作，有焦点提示、名称、当前值和状态。触控按钮点击区域至少 44×44 CSS px。
- 开关和当前时间的文字反馈不刷屏；可通过合理节流的辅助技术状态提示呈现。
- 首次打开给出简短操作提示，不用强制教程遮住场景；帮助可随时重新打开。
- 加载中显示阶段或进度；出错时显示可理解的中文提示，不留空白页面。
- 默认不播放声音。尊重“减少动态效果”偏好，减少相机过渡、光晕脉动和装饰动画。
- “复位视角”“全部恢复自动”“重置场景”功能分开。重置场景恢复 18:30、暂停、默认展示视角及自动灯光。
- 可选使用 localStorage 记忆设置；读取或写入失败时仍正常运行，不依赖它才能加载作品。首次验收使用干净存储的默认状态。

## 9. 资产处理与技术实现

### 9.1 当前资产事实

- 国王大道道具包、12 款护送车包和一份 OW2 猎空模型已下载到当前云环境；下载大小与 ZIP 完整性已核对。
- 实际国王大道包包含 89 个 `.mdl`，护送车包包含 12 个 `.mdl`；目录存在不等于已经验证模型外观、贴图和骨架。
- 莱因哈特、死神和补充小件存在来源目录，但不能将目录中的链接视作已经进入 HTML 的模型。
- 见 [资产匹配表](../assets/catalog/四视图资产匹配.md) 和 [本地包清单](../assets/catalog/local-archive-inventory-v1.json)。

### 9.2 导入流程

1. 从少量代表资产开始：先导入电话亭与护送车，检查 Source `.mdl/.vvd/.vtx`、VMT/VTF 材质和坐标的转换可行性。
2. 采用 Blender 的可用导入路径验证外观、UV、法线、透明和骨骼。转换插件的版本、命令和失败项要记录。
3. 调整角色姿势、简化材质和几何；本版可采用静态定格角色，不要求为了点灯交互先制作整套动画。
4. 重建必要的窗户、室内隔断、灯罩、护盾和闪现曲面；将需要独立交互的材质和物件分离。
5. 清理未使用的模型、纹理、骨骼和动画，统一原点与缩放，再导出网页适用资源。
6. 仅将实际需要的场景和贴图嵌入最终 HTML；不把整套地图或模型库打包进去。

原始模型不可用时，继续完成独立部分，再用明确记录的重建模型补足。最终不能保留临时方盒作为英雄或主体成品；重建内容须与现有风格和角色轮廓一致。需要 Cascadeur 的复杂动作属于额外动画流程，不作为本版交互展示的前置依赖。

### 9.3 材质和灯光拆分

- 地面、围栏等静态物件可合批；四个房间窗面和每盏灯必须保留独立的状态入口。
- 不能共用同一个可变发光材质，导致点击一间房把其他房也一起点亮。可共享基础参数，发光状态独立。
- 每个房间的内光、窗面发光和相关光晕绑定到同一个房间 ID。
- 暖光投射可用少量真实局部光配合受控的光斑/材质效果，但日夜主光变化必须影响三维几何。
- 动态直射阴影优先留给太阳/月光；局部灯光阴影按性能预算分配，避免七个分区全部使用高成本阴影。

### 9.4 单文件封装

- 建议 Three.js，制作阶段使用固定依赖版本与可重复构建，交付时将运行时代码打包到内联脚本。
- 优先采用已减面、贴图优化的 GLB 与内嵌 PNG/JPEG。直接从内嵌字节解析资源，不在 `file://` 页面中 `fetch` 相对模型路径。
- 第一版优先避免运行时依赖额外 WASM、Worker 或解码文件的方案；需要压缩解码器时，所有代码及资源一并内嵌，并重新验证直接打开和离线加载。
- 图标使用内联 SVG，字体使用系统字体；运行时没有必须访问外网的资源请求。
- 源码按场景搭建、相机、灯光状态、时间模拟、拾取、界面、资源与存储分层，避免多个事件重复修改同一状态。
- 不依赖 eval、远程脚本或浏览器不支持的本地文件权限。
- 保留资源来源、作者和许可记录；最终 HTML 仅嵌入可用于本次交付的资源。对已有明确禁止再分发的资产，先解决使用范围或采用重建替代。源资料链接不能充当已经实现的场景内容。

## 10. 性能、兼容与稳定性预算

以下是制作预算，须以最终文件在记录的测试设备上实测，不能据预算提前宣称达到性能：

| 指标 | 标准 |
| --- | --- |
| HTML 大小 | 目标不超过 35 MiB；本版上限 60 MiB，超出先优化模型和贴图 |
| 场景三角面 | 目标不超过 25 万，上限 50 万；只统计实际提交场景，不把隐藏原始库算成优化成果 |
| Draw calls | 桌面默认画质目标不超过 120，上限 180 |
| 贴图 | 以 1K 为主，共用图集可用 2K；不默认堆叠 4K/8K |
| 真实局部光 | 同时参与渲染的数量控制在 8 以内，独立灯光逻辑不受此数量限制 |
| 桌面帧率 | 1080p、记录的主流集成显卡设备上，连续操作 60 秒平均达到 45 FPS，目标 60 FPS |
| 移动端帧率 | 记录的一台近年中端实机，默认降档画质下连续操作平均达到 25 FPS，目标 30 FPS |
| 首次可操作 | 目标桌面不超过 8 秒、移动端不超过 15 秒；本地文件加载，另报解析/解码耗时 |
| 连续操作 | 运行 10 分钟，无持续内存上涨、崩溃、失控增亮或累计事件监听 |

设备记录包含型号、CPU/GPU、系统、浏览器版本、画布分辨率和 DPR。无法使用移动实机时，明确标为“未实测”，不能用桌面缩小窗口代替性能验收。

画质降档顺序优先为降低 DPR、阴影分辨率、关闭额外后期效果和减少装饰动画；不得删除核心角色、房间控制或时间系统来达标。移动端建议 DPR 上限 1.5，桌面上限 2，渲染质量可动态调整。

兼容基线：当前稳定版 Chrome、Edge、Firefox 的桌面 WebGL2 环境，至少实际验证 Chrome 与 Firefox；Safari 和移动浏览器作为补充兼容项单独报告。检测到 WebGL2 不可用时显示说明与静态预览，明确三维交互不可用，不能把静态预览当成功加载。

## 13. 本版完成定义

只有当场景造型、七个独立灯光分区、四个房间、手动/自动优先级、时间系统、相机预设和单文件离线运行均完成并验证，才称本版 HTML 制作完成。

额外动画、音效、天气、角色选装和更复杂室内互动可以后续扩展；不能在核心项尚未通过时，以附加效果替代交付。
